# Сторож линии маркировки

Автономный пакетный анализ журналов станции, ПЛК, маркиратора и коробов.
Python 3.12, только стандартная библиотека, без сети.

## Запуск

```bash
python3 найти.py /путь/к/смене > ответ.csv 2> состояние.json
```

Файлы `station.log`, `plc.csv`, `laser.log`, `boxes.csv` должны лежать в указанной
папке или её подпапке `data`. Исходные файлы не изменяются. Анализ выполняется
на временном снимке; изменение исходных файлов во время обработки отклоняет
результат. Для работы нужны согласованные завершённые файлы смены.

По умолчанию включён автономный режим (`--strict` — его явный синоним).
CSV в stdout содержит доказанные случаи А, Б, В и Г. JSON в stderr содержит
статус, причины неполноты, найденные случаи, интервалы S1, известные владельцы
нанесений и SHA-256 входных файлов. `schema_version` сейчас равен 1.

| Код завершения | Статус JSON | Значение |
|---|---|---|
| 0 | CLEAR | В проверяемых цифровых данных нарушений и неразрешённых участков не найдено |
| 10 | ANOMALIES | Есть доказанные нарушения |
| 20 | INCOMPLETE | Разбор неполон; доказанные случаи сохранены, причины перечислены в `issues` |
| 2 | INPUT_ERROR | Вход непригоден или превышен лимит обработки; CSV не выдаётся |

Для автоматизации любой код, кроме 0, требует обработки как тревога или ошибка.
Отсутствующий/неразбираемый JSON или аварийное завершение процесса также являются
ошибкой, а не чистой сменой. Нельзя интерпретировать пустой CSV как отсутствие
нарушений без проверки статуса. Программа не управляет оборудованием и не
отправляет уведомления внешним сервисам.

## Что доказывается

- Проходы S2 сопоставляются с интервалами S1 и ходом ленты, включая известные
  остановки, пуски и изменения скорости.
- Записи коробов сравниваются с установленным физическим наполнением; двойная
  запись кода выдаётся как Г, без повторного учёта А.
- Код тубы связывается с нанесением только при единственном возможном владельце.
- `MarkCount` проверяется с учётом интервала между запросом и ответом.
- Потерянные подтверждения сопоставляются с отправками кодов. Несколько потерь
  могут доказывать повторное нанесение кода, не определяя номера туб.
- Ненулевые начальные счётчики считаются базой. Их сброс внутри файла, испорченные
  поля и противоречивые входы не превращаются в успешный результат.
- Несогласованные эпохи часов запрещают выдачу физических утверждений А/Б/В.
  При наблюдаемом переводе используются консервативные границы возможного
  движения; неизвестная длительность сохраняется в диагностике.

CSV: `вид;время;туба;код;короб;причина`. Точное расчётное время S1 выводится только
при однозначной привязке нанесения и известном ходе ленты. Иначе поле остаётся
пустым, а доступные границы опроса находятся в `s1_intervals`. При доказанном
дубле с неизвестным первым номером номера не выдумываются; известные владельцы
указаны в `known_print_owners`. `NoRead` обозначает неопределённый КИ.

## Границы наблюдаемости

`CLEAR` относится к цифровым журналам (`scope: digital_logs_only`). Ручное
снятие тубы после S2 не оставляет в них следа. Для контроля такого действия нужен
датчик/журнал оператора; голосовое не обрабатывается этим скриптом автоматически.

Физическое наполнение ручного короба не подтверждается одной записью его кодов
и отмечается как INCOMPLETE. Недостаточные интервалы опросов, потерянные сведения
о кодах, неполный короб,
неопределённая граница этикетки или перевод часов могут приводить к INCOMPLETE.
Это самостоятельная машинная тревога, а не молчаливый пропуск. Перенумерация
физических туб через сброс счётчиков ПЛК без идентификатора запуска не угадывается:
в таком случае возвращается INPUT_ERROR.

Пределы одного запуска: 64 МБ на входной файл, 200 000 наблюдаемых входов S1,
110 секунд вычислений. При превышении возвращается ошибка. Программа анализирует
снимок смены, а не является постоянно запущенным процессом мониторинга.

## Совместимость

```bash
python3 найти.py /путь/к/смене --compat
```

`--compat` сохраняет прежний CSV-разбор и оценки времени по опросам. Этот режим
предназначен для сравнения с предыдущими версиями; его нулевой код завершения
не означает доказанную полноту. Для автономного контроля используйте режим
по умолчанию.

## Проверки

```bash
python3 -m unittest -v
```

Независимый генератор создаёт физические смены на трёх скоростях, с тремя
размерами короба, остановкой/ускорением и успешной/неудавшейся выбраковкой.
Отдельные сценарии проверяют перезапуски, потери подтверждений, повреждённые
входы, изменение снимка, лимит времени, повторный запуск и машинные статусы.
